### Release 4.5.3:

- **A Clusters page for Super Admins (4.5.0).** /clusters lists the built-in cluster and every registered one, with health, deployments and a history of every change. No kubeconfig reaches the browser.
- **Registered clusters (4.5.0).** A setup script prepares a cluster with two Clouve service accounts, and registering checks the file, connection, identity, permissions and readiness. Setup jobs install what's missing.
- **Organizations on their own cluster (4.5.0).** An assigned organization's new deployments go to its cluster, which the install form shows under "Region". No existing deployment moves, and prices don't change.
- **AI Studio previews on every cluster (4.5.0).** Each cluster has its own preview domain. Once a cluster uses per-deployment preview keys, one tenant can't sign preview cookies for another.
- **Create and delete clusters (4.5.1).** "Create a cluster" builds a GKE cluster next to cluster-1, puts its credentials straight into Secret Manager, registers it and sets it up. "Delete cluster" is refused while deployments or assigned organizations remain.
- **Creation settings (4.5.1).** They hold a kill switch (Off, Dry runs only, On) that starts at Off, a limit on created clusters, the regions and prices, and a "Spot node pools" switch. A dry run changes nothing.
- **Spot node pools (4.5.1).** Where the settings offer them, a created cluster can have a Spot pool: apps prefer Spot nodes and fall back to the regular pool, and Clouve's own components stay on regular nodes.
- **No password in the AI Assistant's sign-in URL (4.5.1).** meso posts the sign-in as a form, so access logs no longer record the password.
- **Host aliases (4.5.2).** A public container can declare up to three aliases, each with its own host, title, icon, admin path and custom-domain field. An alias adds no container, so the price stays the same.
- **Stricter checks on names and domains (4.5.2).** Container names must be valid Kubernetes names, and custom domains are checked on every save. A custom domain chosen at install no longer leaves the deployment stopped.
- **Four older security problems fixed (4.5.2).** The stage no longer compiles publisher text as a template or trusts unchecked container names, the deploy actions' template context no longer holds credentials, and apex Clouve domains no longer pass as custom domains.
- **Listing rules on the server (4.5.3).** thermo refuses template text and unsafe values, icons from outside the publisher's own organization, and admin paths the rule refuses, on every save and at the stage. Running deployments don't change.
- **Same-day refunds (4.5.3).** A cancel within 24 hours of a charge refunds the whole charge, settled or not. Each charge gets one receipt, and a Buy more charge that Braintree refuses as a duplicate now gets a plain sentence instead of a decline.
- **Resume and clone (4.5.3).** Resume brings each workload back to the replica count it had when paused. A clone gets its own AI Assistant passwords, its own ai- host and its own registry robot.
- **The AI Assistant (4.5.3).** Claude Code is pinned and its download checked. A user name pauses after 10 wrong passwords in 15 minutes, a page reload ends the old terminal session, and the assistant keeps no SSH host keys for its sibling apps.
- **Headers, certificates and logs (4.5.3).** The ingress stops sending HSTS includeSubDomains and keeps query strings out of its access logs, and removing a custom domain deletes its certificate. thermo's and iono's build logs stop echoing secrets, and account emails and the cluster password re-check get limits.
- **Operator tools (4.5.3).** Scripts run the data checks, a scan finds values the old domain rewrite mangled, registry robots can be scoped to a deployment's own projects, and new tooling rotates an environment's owner key.
